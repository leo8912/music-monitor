## 1. 环境要求

| 组件 | 版本要求 | 备注 |
|------|---------|------|
| Python | 3.11+ | 本项目 `pyproject.toml` 要求 `>=3.11`，实测 3.13 可用 |
| Node.js | 18+ | 前端 Vite 7 要求 Node 18+，实测 v22 可用 |
| npm | 9+ | 随 Node 安装 |
| Redis | 可选 | **本地默认关闭**，任务队列走进程内 inline 模式；仅 Docker/生产环境启用 |

## 2. 一键启动（推荐）

项目根目录已提供一键脚本，无需手动分开启动前后端：

```powershell
# 开发模式：后端 :8000 + 前端 Vite :5173，自动打开浏览器
.\run_dev.ps1

# 单进程模式：先构建前端，仅由后端 :8000 直接托管 SPA，自动打开浏览器
.\run_dev.ps1 -Prod

# 跳过依赖安装检查（环境已就绪时更快）
.\run_dev.ps1 -NoInstall
```

也可以直接双击 `run_dev.bat`（等价于开发模式）。

脚本会自动完成：
1. 检查/创建 `.venv` 虚拟环境并 `pip install -r requirements.txt`
2. 检查 `web/node_modules`，缺失时 `npm install`
3. 启动后端、前端（或构建前端），等待服务就绪
4. 自动打开浏览器

> 停止方式：关闭弹出的命令行窗口即可（后端与前端各一个窗口）。

## 3. 手动启动（分步说明）

### 3.1 初始化

```powershell
# 1) 创建虚拟环境（若不存在）
python -m venv .venv

# 2) 安装后端依赖
.\.venv\Scripts\pip install -r requirements.txt

# 3) 安装前端依赖
cd web
npm install
cd ..
```

### 3.2 启动后端

```powershell
# 方式 A：直接运行（推荐，会执行 DB 迁移/建表）
.\.venv\Scripts\python.exe main.py

# 方式 B：uvicorn 手动启动
.\.venv\Scripts\uvicorn main:app --host 0.0.0.0 --port 8000
```

后端监听 `http://localhost:8000`。

### 3.3 启动前端（开发模式）

```powershell
cd web
npm run dev
```

前端 dev server 监听 `http://localhost:5173`，已配置代理：
- `/api` → `http://localhost:8000`
- `/ws` → `ws://localhost:8000`（WebSocket）
- `/uploads` → `http://localhost:8000`

### 3.4 单进程模式（生产/演示）

```powershell
cd web
npm run build          # 产物输出到 web/dist
cd ..
.\.venv\Scripts\python.exe main.py
```

`main.py` 检测到 `web/dist` 存在时会自动挂载 SPA，直接访问 `http://localhost:8000` 即可，无需 5173。

## 4. 配置说明

配置文件：`config/config.yaml`（由 `config.example.yaml` 复制而来）

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `auth.username` | `music` | Web 登录账号 |
| `auth.password` | `password` | Web 登录密码（建议修改） |
| `auth.secret_key` | 随机生成 | 会话签名密钥，首次启动自动生成并写回 |
| `database.url` | `sqlite+aiosqlite:///config/music_monitor.db` | 数据库（本地 SQLite） |
| `redis.enabled` | `false` | 本地默认关闭，使用进程内任务队列 |

> 注意：`config/config.yaml` 已被 `.gitignore` 忽略，属本地私有配置；
> 仓库中只跟踪 `config.example.yaml` 模板。

| 功能 | 操作路径 | 预期结果 |

## 8. 常见问题

### Q1: 端口被占用
- 8000：已有后端在运行，先关闭旧进程或换端口
- 5173：已有前端在运行，同样先关闭

### Q2: `pip install` 报 pyncm 找不到
pyncm 已从 PyPI 下架，`requirements.txt` 使用本地 `./vendor/pyncm-1.8.1-py3-none-any.whl` 安装，属正常。

### Q3: 登录报"无法导入 fastapi"
Pylance 可能指向了错误的解释器（如 `.ruffenv`）。在 VS Code 中：
`Ctrl+Shift+P` → `Python: Select Interpreter` → 选择 `.venv`。

### Q4: 数据库需要重置？
删除 `config/music_monitor.db` 后重启后端会自动重建表结构（Alembic 迁移）。

### Q5: 运行 `run_dev.ps1` 报"表达式或语句中包含意外的标记 / 字符串缺少终止符"
这是 **PowerShell 5.1 编码解析问题**：`.ps1` 文件必须是 **UTF-8 with BOM**。
若文件被编辑器保存为 UTF-8 无 BOM，Windows PowerShell 5.1 会按 ANSI（GBK）解码，中文注释乱码后破坏引号配对，导致报错行与实际不符（常报在 `}`、`-Command "..."` 附近）。
- 本仓库 `run_dev.ps1` 已修复为 UTF-8 with BOM，可直接运行；
- 若再次出现，请勿用编辑器"无 BOM"保存该文件，或在 PowerShell 5.1 中改用 VS Code 默认保存；
- 检查方法：文件首 3 字节应为 `EF BB BF`。

### Q6: 脚本卡在"等待后端就绪"，但后端实际已启动
`run_dev.ps1` 的健康检查已改用 `.venv` 的 Python（`urllib` + `127.0.0.1:8000`）探测，
规避 PowerShell 5.1 `Invoke-WebRequest` 的两类已知问题：
- `localhost` 在 PS 5.1 中可能先解析到 IPv6 `::1`，而后端只监听 IPv4，导致连接挂起；
- PS 5.1 的 `Invoke-WebRequest` 在 `$ErrorActionPreference='Stop'` 下 `-TimeoutSec` 并不可靠。

若仍提示未就绪：请查看弹出的后端窗口日志确认实际报错（如端口冲突、依赖缺失）。

## 9. 目录速览

```
main.py                # FastAPI 入口（含 lifespan 初始化、SPA 托管）
core/                  # 配置/数据库/队列/调度/WebSocket 等基础设施
app/
  api/v1/              # REST API 路由
  services/            # 业务服务层（Service 模式）
  repositories/        # 数据访问层（Repository 模式）
  workers/             # 任务定义（arq / inline 双模式）
  models/              # SQLAlchemy ORM 模型
  notifiers/           # 通知（企业微信/Telegram）
web/                   # Vue3 前端
tests/                 # pytest 测试
alembic/               # 数据库迁移脚本
```
